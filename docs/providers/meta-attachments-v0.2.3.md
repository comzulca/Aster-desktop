## Complete bounded interpretation, not silent omission

The provider's documented native PDF coverage includes first-100-page text and first-50-page visual processing; Aster deliberately admits at most **20 PDF pages per batch**. Every admitted page is processed in order at 150 DPI for native preview/local history, and the original native PDF is transmitted for the first separately approved reading. ## Temporary originals and available-only continuation

Native-selected source paths never enter renderer IPC. Originals are immutable bounded host-memory snapshots with opaque process/conversation/request/expiry binding, not persistent uploads or history. The source file is never removed or modified. Removal, replacement, chat switch, expiry, cancelled review, quit or restart invalidates the temporary allocation and grant. Zeroising owned buffers is not a promise of erasure from paging/crash dumps/other copies.

A new selection replaces the complete temporary batch before the selector opens. Cancelling yields an empty batch rather than restoring previous original bytes/IDs; the text draft is retained. Processed text is embedded in the saved user message without a native-page-view button. The local native processed-view command below is offered only for image/PDF derivatives, not as an unavailable text-file reader.

History stores only admitted processed content and responses in the separately encrypted current-user `processed-media-v1` domain, with bound versioned user-entry metadata. Original PDF/image bytes, paths and active approval IDs have no persistent schema field. Legacy history/financial bytes/domains remain frozen; new snapshots use v2. Per-file media records are at most 6 MiB JSON, with 128 MiB/512-record domain bounds and 16 MiB cumulative processed content per conversation, including inert text and PNG pages. Orphans/recovery records remain unreferenced and do not restore a grant or reclaim quota automatically. See [ADR-0020](../adr/ADR-0020.md).

`review_processed_attachment` takes only conversationId, requestId and attachmentId, authenticates the visible undeleted user entry and opens a **local native image/PDF page view**, returning only `{viewed: boolean}`. It sends nothing to Meta and is not a disclosure approval. Historical pages are not automatically resent and never reconstruct a PDF. Continuation includes only available eligible text, a truthful note that a native original is absent, and completed eligible answers. **Reattach the PDF for another complete native reading and approve the new exact request separately.** No prior upload/grant/approval is reused.
