## Fixed dispatch and native content

Host-only credentials, normal TLS, no redirects/unintended proxies, one immutable reviewed allocation, streaming, no automatic retry/fallback and no tools remain unchanged. The closed eight top-level body fields remain model, messages, stream, stream_options, reasoning_effort, max_completion_tokens, n and store. Typed media changes only the admitted user-content representation; protocol/policy 4 and the separately reviewed 24-MiB body bound replace the previous text-only seam. No generic renderer JSON, URL or destination override is admitted.

For a fresh admitted PDF, a user content part uses the documented `type: file` / `file.filename` / `file.file_data` form, with a `data:application/pdf;base64,...` value created from the exact immutable temporary native PDF bytes. It is **not a raster-only substitute**. Host-created image parts use `type: image_url` with a `data:image/png;base64,...` value created from metadata-free lossless normalised PNG. Public/remote URLs and the Files API upload/storage route are not used. Text/data contents are inert UTF-8 inside the bounded composed prompt, not executed XML/YAML/JSON/formulas or an alternate upload purpose.

Lossless PNG describes encoding the normalised decoded RGBA8 pixels, not preserving the original file bit-for-bit. Sixteen-bit samples may be quantised to eight bits and JPEG colour-space conversion can change representation. Decoded EXIF orientation is applied before PNG generation; its metadata is discarded. Inspect the processed preview before approval. The owner's processed-only history decision is not an original precision/metadata guarantee; native PDF dispatch still uses the exact original bytes.

The host constructs and validates the complete allocation before the native disclosure; approval binds its exact bytes/hash, full available prior context, classification, model, transformation information and fresh attachments. Dispatch must consume that allocation without rebuilding an equivalent JSON body. The trusted native visual viewer must show every processed page/image at navigable scale plus complete text; raw base64 or a filename alone is insufficient visual disclosure. A PDF's page preview does not reveal all source metadata, hidden objects or embedded files, so the owner declaration explicitly covers the complete native source. No renderer Boolean, model output, document text, saved reference or preview completion can approve itself.

## Complete bounded interpretation, not silent omission

The provider's documented native PDF coverage includes first-100-page text and first-50-page visual processing; Aster deliberately admits at most **20 PDF pages per batch**. Every admitted page is processed in order at 150 DPI for native preview/local history, and the original native PDF is transmitted for the first separately approved reading. Refuse oversized, incomplete, encrypted/password-protected or unsupported input rather than omit pages and label a partial result complete. The model can still misunderstand a correctly admitted full input; full-file admission does not guarantee answer accuracy.

The direct extension set is PDF, TXT, MD, JSON, XML, YAML, CSV, TSV, PNG, JPG, JPEG and static GIF. DOCX/XLSX/PPTX must be converted externally to a complete PDF by the owner with a trusted tool, such as their local LibreOffice; the owner checks pages, slides, sheets, print ranges and visual layout. No internal Office parser, converter invocation or LibreOffice dependency is introduced. ChatGPT's extensions/file caps, unlisted code/video inputs, legacy Office, animated GIF and provider-supported additional modalities are not automatically Aster capabilities.

Product limits are stricter independent policy: four files; 8 MiB source per file and 16 MiB source per batch; text parser ceilings 128 KiB/file and 256 KiB aggregate, with the full sending prompt still at most 32 KiB; PDF 20 pages per batch; image/page dimension at most 4,096 and decoded pixels at most 4,194,304; 4 MiB normalised PNG per file, 16 MiB per batch and 64 MiB decoded RGBA.
