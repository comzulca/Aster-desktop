# ADR-0018 — v0.2.3 bootstrap visibility and attachment trust boundaries

Date: 3 October 2026; reconciled 4 October. Status: accepted bounded presentation and external Office-conversion design; ADR-0019/0020 now fix processing and media-history details. Fresh native/installed qualification remains separate. Trace: SPEC-0005 / UX-014..015, FR-027..028, NFR-008..009, SEC-026..028 / AC-065..073 / T-075..083.

Keep the v0.2.2 dark config and external blocking stylesheet. Microsoft documents a fixed process-local `WEBVIEW2_DEFAULT_BACKGROUND_COLOR=FF1B1F20` before controller startup; this covers the initial colour without user/machine environment or browser-argument changes. Locked Wry already attempts early controller options; additional initial-colour handling is mitigation, not a proven second-flash cause.

A bootstrap reveal has no generic renderer show/hide grant. Native state admits only one authenticated-main shell-ready transition with a closed versioned DTO, bound to that process/window, no label/URL/action parameters. In response to the owner's proposal to prepare rendering before presentation, the window starts invisible and requests one reveal after shell readiness and a 6,000-ms minimum from native setup. An independent 10,000-ms deadline attempts presentation even without JavaScript/readiness, subject to an available OS/UI loop; native show/scoped-hook failure remains possible and is diagnosed. This is not absolute visibility, a GPU/runtime cure or completed-paint proof. Shell readiness must not wait for credentials/status/history; replay/deadline races are idempotent, never re-hide/focus-steal and never approve provider/data operations. Animation frames are a scheduling signal, not native painting evidence. Closed, capped in-memory monotonic phase/result diagnostics contain no content, names, paths, URLs, identities or keys.

Effort and classification share a popup but not state or authority. No option is an implicit classification, approval or send; classification starts unset. Existing modal/busy/draft guards and caption/zoom invariants continue.

Attachment pipeline: native selected file -> identity-pinned bounded immutable original -> independently bounded restricted processing -> processed preview/hash -> temporary conversation-bound opaque identifier -> native full-request eligible-data/visual review -> immutable host-owned typed Meta body -> separately reserved one-shot dispatch -> bounded processed-content history/response. Original bytes and path never become renderer filesystem or model authority. Removing/restarting invalidates all grants; no original is persisted. The owner requests full visual interpretation. The owner explicitly accepts safe external PDF conversion using their own LibreOffice or another tool outside Aster. DOCX/XLSX/PPTX are conversion-guidance formats, not direct imports; there is no internal Office reader/converter, LibreOffice invocation or converter dependency. The owner must verify exported pages, slides, sheets and print ranges in their chosen tool before selecting the PDF. Host-owned safe preview must meaningfully show the same visual content being sent; raw base64 alone is insufficient consent.

Do not upload to Files API, fetch remote URLs, invoke Office automation, execute macros, or add generic shell/FS/window/plugin permission. Reject active/external archive content and oversized/deep/expansive resources. Complex-worker timeout must actually terminate the worker, not only stop awaiting a parser thread. New processed-media history needs a separately versioned migration; existing text-history records and financial obligations are not rewritten. Contributor training/prohibited-data restrictions and complete exact-body review remain mandatory. Whole-context pricing/bounds must be rechecked; no live request is authorised by this ADR.

Residual risks: conversion may alter Office visual layout/print ranges, unsupported/encrypted/active objects may require rejection, public images can contain personal data, full-file interpretation is not guaranteed model correctness, and OS/GPU/runtime-specific startup flashing still needs installed owner verification. Maintainers own parser/visual/native checks; owner must supply eligible documents and final installed observations. No production, live account or native-flash PASS is asserted.

Owner PDF decision: native PDF egress from the immutable temporary copy; all-page processed images and responses persist, not original PDF bytes. Another full native reading requires new explicit attachment. Historical processed pages remain local display material and no original/grant is reconstructed. Native review binds the exact PDF hash/body and derived pages, with a clear hidden-content/metadata eligibility declaration. The all-page visual preview is not a claim to detect every hidden PDF object. See SPEC-0005 and ADR-0019 for processing/body/protocol bounds.
