# ADR-0013 — Separate native Meta credential

**v0.2.3 applicability — 4 October 2026, Edinburgh / Europe/London:** dated evidence below retains its original source, version and result; it does not qualify changed v0.2.3 bytes. Unchanged constraints remain subject to the [current documentation index](../V0.2.3-DOCUMENTATION-INDEX.md) and [SPEC-0005](../specs/SPEC-0005.md). The owner authorises a v0.2.3 PR and GitHub checks only, not merge, release or signing. Final-source, package, native and live qualification require independent evidence in [LOCAL-V023-0001](../qa/LOCAL-V023-0001.md). No retired provider, historical grant or old PASS is reactivated.

**v0.2.2 applicability, 3 October 2026:** retained requirements/contracts apply only where unchanged; retired providers, disabled capabilities and older dated results are not current authority or new-source PASS. [SPEC-0004](../specs/SPEC-0004.md), [ADR-0017](../adr/ADR-0017.md) and [LOCAL-V022-0001](../qa/LOCAL-V022-0001.md) govern active zoom/startup changes and fresh evidence. Earlier evidence remains source-bound history; the later owner-reported v0.2.1 startup flash is recorded separately. The entire original v0.2.1 checkout/installer is unchanged.

**v0.2.1 applicability, 3 October 2026:** [SPEC-0003](../specs/SPEC-0003.md) extends the unchanged Meta Contributor/protected-history/financial contract recorded below. Only its explicit visual/menu/caption/local-editing amendments supersede earlier UI clauses. Prior source, command, date, PASS and catalogue statements remain dated v0.2.0 history, not qualification of changed v0.2.1 code. Fresh exact-source, installed/native and live statuses belong in [LOCAL-V021-0001](../qa/LOCAL-V021-0001.md); real key/live activation is deferred until the new engineering build exists.

Compatibility decision, 2026-10-03: preserve the documented pipe form and also admit the bounded opaque `LLM_` form observed in the separate owner-authorised catalogue diagnostic. Require 8..256 total ASCII bytes and an opaque suffix of at least 12 alphanumeric/underscore/hyphen/full-stop characters; never infer an account identity from it, alter separators or trim/repair native input. Keep entry, zeroising allocations, revocation-before-write, host-only Bearer use and the fixed credential target unchanged. Extend synthetic syntax/decoder and source-secret guards for the new form. The provided test file was read only by an isolated diagnostic process; it is not imported by Aster, copied to its store, included in evidence or a native credential acceptance result. The catalogue observation proves neither generation rights nor legal/financial eligibility. No new endpoint is registered in the app.

Accepted for implementation, 2026-10-02. Use fixed target AsterDesktop/MetaModelAPI/v1 in Windows Credential Manager. Accept only bounded documented direct Model API key syntax; syntax is not entitlement. Native owner-window entry/delete confirmation and zeroised buffers; no key bytes through WebView, IPC, prompts, `.env`, logs, builds or CI. Never read/reuse/rename/delete the historical NVIDIA object during this migration. Synthetic diagnostic targets and fake keys remain isolated. Change account/credential invalidates automatic continuation authority but does not reset financial reservations or conceal pending spend.
