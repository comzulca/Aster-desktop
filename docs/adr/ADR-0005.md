# ADR-0005 — Preserve real credentials through an isolated GUI diagnostic

Date: 2026-09-30 UTC. Status: implemented in historical `b0610c5` and retained in protocol 2; latest working-tree automatic fixtures pass, while the frozen-source run, package binding and owner GUI acceptance remain NOT RUN. Trace: FR-013 / SEC-001, SEC-002, SEC-010 -> TM-001, TM-012, TM-013 -> AC-013, AC-020, AC-026 -> T-028, T-033, T-034.

## Context and authority

The owner confirms an existing real NVIDIA credential must be preserved. No test may replace, delete, export, log or ask for its value. Tests use the existing owner administrator account with a normal/non-elevated token; no new account, security change, credential-target override or additional live request is authorized. Two separately authorized plain-text canaries remain unexecuted and reserved for the final candidate.

## Decision

Add one exact offline CLI diagnostic, `--aster-credential-gui-fixture`, before normal Host/Tauri/provider initialization. The launch selector is closed: no arguments selects normal startup; exactly one known credential/small-review/large-review flag selects its isolated diagnostic; every other invocation, invalid Unicode argument, extra argument or attempted override fails closed and exits without normal startup. The fixture has no IPC, renderer, provider, network, project or production CredentialStore route. It reads no target/key/path/URL from argv or environment.

The diagnostic creates one opaque internally generated target under the distinct literal namespace `comzulca/aster-desktop/credential-gui-fixture/`, with bounded closed ASCII nonce components. Only typed fixture wrappers may address it; validate the namespace/shape before every OS operation. Never enumerate credentials. Any raw present entry, including malformed data, denies creation; absence is established only by ERROR_NOT_FOUND. The normal production CredentialStore retains its original fixed target.

Native prompts identify the exact synthetic target and warn never to enter a real credential. The only admitted diagnostic password is known non-secret `synthetic-fixture-key-123`. Bounded input, copied blobs and decoded strings are zeroized, including rejected input. Shared CredUIPromptForCredentialsW uses DO_NOT_PERSIST; the host explicitly writes only after fixture admission and rechecking absence. Manual Control Panel entry/read/remove is independent evidence of actual GUI representation, not a claim about documented encoding.

Fixture read-back additionally admits only the exact generated target and synthetic username, Generic type, zero flags/attributes, empty alias/comment and bounded supported persistence (local-machine or enterprise). After the diagnostic write, retain only a host-private non-secret snapshot of admitted target, LastWritten and persistence. Deletion requires a separate default-cancel native confirmation, then exact fixture-state/snapshot revalidation after both denial and acceptance and again immediately before deletion; denial performs zero deletion. A same-value rewrite with changed recorded generation is denied too. Wrong/malformed/foreign/changed or ambiguous state is left untouched. There is no unconditional persisted-credential Drop/error/panic/interrupt cleanup; scrubbing/freeing an OS read allocation is not credential deletion. Report only fixed stage classifications and the non-secret generated target for owner cleanup. Do not output supplied password bytes, headers or arbitrary credential metadata.

## Limitations and verification

Generic Credential APIs have no atomic expected-value compare-and-write/delete against a malicious same-user racer. Namespace isolation excludes the production credential; prechecks are not a CAS claim. Same-user credential access remains a documented residual. Native MessageBox fixture consent does not certify production Tauri caller/window authentication, dialog guard or deletion wiring; preserve that separate evidence boundary.

T-033 automated fake-backend boundary/lifecycle tests must precede owner T-034 execution. The manual procedure exists before behavior implementation. Actual GUI, renderer IPC/log/file inspection, install/UI/restart/uninstall, third-party notices and live canaries stay independently NOT RUN. Protocol 2 has nine closed shipping commands and exactly four workspace capability Booleans; the diagnostic grants none of them and cannot exercise the provider or workspace. Issues #11/#12 stay open until their actual requirements pass.
