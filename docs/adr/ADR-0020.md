## Selection and temporary original

Only the authenticated host opens the native selector. Its selected path never crosses renderer IPC. A fixed local NTFS drive and every ancestor directory are checked and pinned without delete-sharing; the selected regular file is opened without write/delete-sharing, with OPEN_REPARSE_POINT. Deny UNC/device/drive-relative/ADS/SUBST/mapped-drive paths, sensitive path components, reparse points, hardlinks, conflicting sharing, identity/size/time drift and over-limit reads. The source is never changed or removed. The bounded immutable copy is held in zeroising host memory, never a disk temporary file or history record. This does not promise erasure from OS paging, crash dumps or allocator copies outside the owned buffers.

Import is all-or-nothing for a selected batch. Four attachments, 8 MiB each, 16 MiB original bytes, 16 MiB processed PNG bytes, 64 MiB decoded RGBA and 20 PDF pages are aggregate admission ceilings. Processing output must match the independently calculated original SHA-256. Native labels are at most 120 UTF-8 bytes without control/bidirectional formatting. Text/data remains inert and the composed sending prompt retains its 32-KiB bound. DOCX/XLSX/PPTX are owner-converted externally to PDF; no Office reader, LibreOffice invocation or converter dependency is added.

An opaque 32-lowercase-hex identifier is issued by the host. Every imported allocation binds to one conversation, one process epoch and a monotonic 300-second expiry. The complete requested ID set is checked for duplicates, unknown/stale/cross-chat values and counts before consuming the batch once for a new bound request. Removing, replacing, switching conversations, cancelling a review, expiry, normal quit or restart invalidates originals and grants. Empty current attachment state cannot resurrect a previous allocation. No ID is an approval or filesystem authority. The registry returns its owned allocation, not a second path read or a freely cloned original.

An independent host cleanup checks expiry once per scheduled second and drops idle expired originals without depending on renderer actions; grants deny after their exact monotonic deadline. Scheduler latency and OS paging/crash copies prevent a real-time or secure-erasure guarantee. A new native selection replaces the complete earlier batch even when cancelled; the returned empty batch is authoritative and unsent draft text is preserved.

## Persistent representation and backward compatibility

Existing `history-v1`, `budget-v1` and `terms-v1` names, financial records and historical bytes are frozen. The history reader accepts validated legacy record/conversation version 1 and new version 2. Only newly appended snapshots use version 2. The optional user-entry `processedAttachments` field contains bounded metadata, never original/path/base64 content. Legacy records lack that field and are read without rewriting their old bytes. Assistant entries cannot carry attachment references.

Derived content is stored separately in the current-user encrypted `processed-media-v1` private domain: 6 MiB per immutable JSON record, 128 MiB cumulative, at most 512 records. Each record contains one processed file, at most 4 MiB of metadata-free PNG pages encoded as base64, or bounded inert UTF-8 text. The record binds its attachment/conversation/request IDs, source hash, processed hash, page dimensions/count/order, declared eligible class and metadata. A chained sequence detects duplicate, missing, reordered or inconsistent records. The cumulative per-conversation processed-content cap is 16 MiB; no automatic eviction is permitted. Each turn admits at most four file references and 20 PDF pages, plus any separately admitted image pages within the four-file limit and shared 64-MiB RGBA ceiling. Original PDF/image bytes and paths have no schema field. Per-file immutable records keep every record below the 16-MiB design maximum without exceeding the existing text-history record cap.

Each v2 turn additionally stores host-private processed bindings with the exact source and processed hashes and ordered metadata. They must match the visible entry references and the independently encrypted media records. These bindings are absent from legacy v1 records and are not renderer-issued grants. Consumed transient source allocations retain their import deadline; the host rechecks expiry and source hash immediately before dispatch, even after a lengthy native review.

Native disclosure computes one effective monotonic deadline from the earliest admitted-source expiry, capped by 300 seconds from review start. The all-page visual viewer, subsequent exact-body decision and returned approval share that deadline. Viewing pages, moving to another review stage or approval does not restart or extend it. The host rechecks source validity after review and immediately before dispatch; expiry denies sending instead of rebuilding an allocation or restoring a grant.

Host-only cancellation polling now exists in source across both native review stages: a 200-ms timer polls while each modal message pump runs, with additional checks before opening, after return and on approval consumption. Cancellation denies dispatch and unwinds through normal ownership cleanup without extending the shared deadline or granting renderer approval. Message-pump/scheduler delays and OS copies prevent a hard response-time or physical secure-erasure guarantee. Fresh compiler/test/native cancellation/timer/resource-cleanup qualification remains pending; source presence and format checking are not successful execution receipts.

The host appends all processed files durably before appending a user history reference and before network dispatch. A failed media append poisons cached media state until a complete checked replay; it must not allow a provider call or reference to a missing page set. A crash can leave unreferenced encrypted media records. Such orphan records are not shown, restore no grant, and are not automatically deleted, repaired or counted as reclaimed quota. A history reference missing its exact conversation/request/attachment/class/hash binding is corrupt and denies dependent loading or sending; no silent fallback to partial pages. A history append failure likewise denies dispatch. Independent financial reservations retain their existing recovery and no-refund rules.

The host validates a requested local image/PDF page preview against the undeleted conversation and exact user entry. Only a fixed native processed-page viewer receives that derived allocation; renderer IPC receives metadata and a bounded `{viewed: boolean}` result, not approval, arbitrary filesystem paths or a binary-history export. Text attachments appear as inert processed content in the saved composed message, not as a native page-view button. Processed pages are local display content and are never implicitly uploaded in later turns. History continuation contains the reviewed inert text or a truthful native-attachment note and answers. A new full native PDF reading requires the owner to reattach the PDF and approve a fresh native disclosure. Processed page previews do not reconstruct a PDF or reveal every hidden source object.

Media health/capacity is an independent import gate. An ambiguous media append makes attachment import unavailable until a complete validated replay; existing unrelated text history and spending controls remain usable. Conservative preselection requires room for one maximum 6-MiB record, not a quota reservation or a promise that a later four-file batch fits. Actual per-file, aggregate and append checks remain mandatory. Egress separately caps combined native-PDF plus normalised-image inline bytes at 16 MiB and complete serialised JSON at 24 MiB; mixed inputs can therefore be refused even when each individual source/processed ceiling passes.
