# ADR-0023 — truthful spending activation without relaxing admission

Accepted before code, 5 November 2026. [SPEC-0008](../specs/SPEC-0008.md), [threats](../security/THREAT-MODEL-0008.md).

1. Add only a non-secret optional maximum-configuration-expiry field to budget status, computed by the host from the existing policy and 31-day rule. Upgrade the coordinated status contract to protocol 5; keep policy 4, configuration/event/store schemas and old quote replay unchanged. Missing/older status is incompatible, never guessed from a frontend hardcoded policy date.
2. Validate numeric ranges and the exact chosen expiry in the form for actionable feedback. Independently validate on the host before opening review and at fresh commit time. Do not clamp user intent, extend the review window or replace host checks with UI checks.
3. Render the existing allowlisted notice in the currently open dialog, rather than behind its modal backdrop. Explain active/inactive spending from refreshed host status and distinguish an unconfirmed/cancelled change. Entered fields alone are never displayed as activation.
4. Keep host-ready presentation and add a separate composer prerequisite explanation. Use the existing reasoning/classification menu and an explicit Usage-settings action. Do not auto-classify text or weaken native disclosure, authentication, modal/busy, attachment or budget guards.
5. Use only synthetic fixtures in hosted CI. A separately authorised bounded direct Meta probe stays local and does not run the installed app or alter owner credentials/history. Qualify the exact main installer passively after all unchanged gates; preserve all independent manual/live/production limitations.
