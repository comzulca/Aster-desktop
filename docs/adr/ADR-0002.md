# ADR-0002 — Native NVIDIA credential custody and fixed egress

Status: accepted and implemented; latest working-tree credential/provider fixtures pass, while frozen-source/CI binding, installed owner GUI/secret-boundary checks and both live canaries remain NOT RUN. Date: 2026-09-24 UTC; reconciled 2026-10-01 UTC. Owner: credential/provider services. Related requirements: FR-001–FR-004, FR-011, FR-016, SEC-001, SEC-003, SEC-007, SEC-012, NFR-002. Threats: TM-001, TM-003, TM-009, TM-010, TM-012, TM-015.

## Decision

The NVIDIA key is a Windows user-scoped Generic Credential for one fixed provider target such as `comzulca/aster-desktop/nvidia/integrate.api.nvidia.com`, stored with local-machine persistence under the current Windows account. The host owns a native Windows key-entry path and `CredWriteW`/`CredReadW`/`CredDeleteW` custody. A typed renderer command can request *status* (`configured` true/false) or trigger a native host dialog but cannot submit or receive credential bytes. The host holds the key only while constructing the authorized request and disposes of any buffers promptly. Use fake CredentialStore injection in cross-platform tests and synthetic disposable credentials for Windows target tests; never use the user's real key in CI, chat, crash reports or fixture files.

Allow exactly `https://integrate.api.nvidia.com` over TLS, with `POST /v1/chat/completions` and the exact selected model ID. The Rust host alone serializes requests, enforces bounded SSE parsing, rejects redirects/proxies and unexpected model/host changes, and never silently retries or switches providers. Model-provided URLs, bearer tokens and instructions have no authority. Both models are intended to stream; each pair gets its own dated official provider contract, request/response fixtures, usage/cancellation checks and separate live canary once user-provided credentials are available on Windows. The initial attached Muse example uses `stream=false`; it is not evidence that Muse cannot stream.

Sending an ordinary typed message explicitly authorizes disclosure of that message to the selected NVIDIA model. Reading a local project file never automatically adds it to a prompt. A project-bearing request is composed and serialized inside the host, and the owner-HWND native review shows the complete exact body and fixed destination before that **specific request** is sent once. Failed/cancelled egress revokes the snapshot; successful egress retains only the bounded proposal right until its deadline. Do not log prompts, project text, streamed content or Authorization headers by default. Logs contain only request IDs, coarse error classes and redacted operational metadata.

Windows Generic Credentials are associated with the user, not cryptographically restricted to this executable. A malicious process under the same account can potentially read them; this residual risk must be stated in the UI/security docs and managed by Windows account and endpoint protection, rather than promising app-exclusive secrecy. Provider-side data processing/billing is external; no local UI control is a hard billing cap.

## Tradeoffs and evidence gates

Native entry costs implementation effort but keeps the key out of WebView and ordinary IPC. Existing OS Credential Manager APIs are used instead of a repo `.env`, JS storage or renderer-based credential form. Only host-managed HTTPS to NVIDIA is in scope, so network tests can assert zero requests to every other origin. The documented connection, header, idle, total, frame and response bounds must agree with `docs/providers/transport.md` and the versioned spec before activation.

No active live pair claim before its official contract fixture, synthetic credential integration test, redaction test and explicit live canary. Each live canary needs authorization for external disclosure and possible provider cost. Mocked SSE parsing is reported independently. No key or credential existence is inferred from an attached Python snippet.
