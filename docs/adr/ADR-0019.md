## Data and numerical contract

The host supplies only an immutable already-admitted byte snapshot and a closed kind enum; no source path, filename, account identity, credential, destination, registry, command or environment input reaches the worker. A file is at most 8 MiB; at most four files and 16 MiB original bytes per import batch. Office files remain owner-converted to PDF outside Aster: no Office parser, LibreOffice invocation/dependency or generic converter is introduced.

Text/data is strict UTF-8, at most 128 KiB per file and 256 KiB total, and remains inert text. Reject NUL, invalid UTF-8 and over-limit input; do not parse XML entities, YAML tags, formulas, executable objects or arbitrary relationships. The raw text is not a new instruction or permission.

PNG/JPEG/static GIF are decoded with the pinned minimal `image` feature set and regenerated as metadata-free lossless PNG with their full admitted dimensions. No resize/crop/page/frame omission. Each dimension is at most 4,096 and each image at most 4,194,304 pixels. Any animated/multi-frame input is refused, never reduced silently to its first frame. Enforce decoder allocation limits before decode. Bound normalised PNG bytes to 4 MiB per processed file and aggregate decoded RGBA bytes to 64 MiB; enforce a bounded total IPC response in addition to these inner limits.

PDF uses the built-in Windows.Data.Pdf in-memory stream API in the worker, with no path/URL/storage upload. Reject invalid, encrypted/password-protected or unsupported inputs. Admit at most 20 pages, render every page in order at 150 DPI, apply the same per-page dimension/pixel bounds, and refuse if any page or total normalised PNG/RGBA/output/work bound fails. Never return only a prefix of an oversized or incomplete PDF. Metadata-free page PNG plus bounded RGBA is available for trusted preview. Rasterisation is a visual derivative, not equivalent to PDF text extraction/searchable layout or a guarantee of model correctness.

The owner explicitly confirms: send the native PDF from its temporary copy; store only processed page-images and responses; reattach the PDF for another complete native reading. No raster-only PDF egress or durable original is authorised. The parent retains the immutable original transiently; the processing module returns its SHA-256 plus every derived preview page, not an alternate provider request. Restored history must truthfully label processed-only pages and cannot reconstruct the original PDF or its grant. Rendered pages do not expose all hidden PDF metadata/internal attachments/objects; native disclosure includes a separate owner declaration covering those contents. Visual preview alone cannot prove absence of Contributor-prohibited content in a native PDF disclosure. This data decision is resolved, while implementation/native qualification and final-build completion are not asserted.

## Execution boundary and remaining security gap

A fixed child mode of the exact running executable is entered before normal Tauri/credential/history/provider bootstrap. The parent creates that executable suspended with only the fixed worker argument and a sanitised environment. Only dedicated byte-input, bounded byte-output and discarded-error handles may be inherited. Before the primary thread resumes, a private Windows Job Object must enforce: one active process, 256 MiB process/job memory, ten seconds process/job CPU, and kill-on-close. A parent 15-second wall deadline terminates the job, not merely an awaiting thread. Failure to set/assign limits, create a least-privilege token or resume safely denies processing; never fall back to an ordinary unconfined process or in-host complex parser.

Use a restricted primary token with maximum privileges disabled and low integrity if the documented APIs can be applied without changing machine/user settings. This limits some authority but **is not an AppContainer or independently enforced network sandbox**. Job resource ceilings alone likewise do not deny network/file access after a parser compromise. No worker code receives or implements network, path, credential or registry operations, but an effective no-network/filesystem-compromise boundary remains a separate qualification gap; do not call the Job Object complete security isolation. Do not create an AppContainer profile, change ACLs/firewall/security settings, obtain administrator credentials or evade an OS/ESET denial to conceal that gap.

stdin/stdout use a closed versioned binary protocol with fixed magic/kind/count/length fields, capped reads/writes and strict EOF. Unknown kinds, extra bytes, short framing, excessive lengths, malformed pages and worker failures deny the whole operation. Output validation occurs before any renderer/display/storage use; the host does not trust a child success code as proof of complete content. Thread/pipe cleanup must follow hard job termination on cancellation, overflow, timeout or errors. Originals are temporary; no input is written to disk by this module.
