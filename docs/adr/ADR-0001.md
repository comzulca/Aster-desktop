## Decision

Target Windows 11 with a Tauri 2/Rust privileged host and a React/TypeScript WebView. The Rust host owns a versioned, closed registry of provider IDs, allowed IPC commands, project root scope, grants, size/time limits and state transitions. The WebView renders inert text and sends typed intent; its state, model output, local repository instructions and injected content never grant privilege. Restrict the Tauri command permission map to the trusted window and verify the caller for every privileged command. Tauri custom commands are otherwise callable by all app windows/webviews by default; a single-window assumption is insufficient.

At startup no file root, key, network provider request or tool is implicitly active. The user selects a project root through the trusted host's native dialog, producing a host-held identity binding. The renderer never supplies an arbitrary absolute path. A read tool operates only under a short-lived host-issued grant bound to conversation, request, root identity, relative resource, operation, expiry and remaining uses. Unknown IPC keys, forged caller, stale root, duplicate grant consumption and oversized payload deny. The app opens no shell, browser or MCP capability in this version.

The host tracks `UNCONFIGURED → READY → REQUEST_RESERVED → STREAMING → TERMINAL`, plus `PROPOSAL → AWAITING_HUMAN → COMMITTING → VERIFIED|ATTENTION_REQUIRED` when file changes are enabled. A cancellation before mutation may reach `CANCELED`; cancellation after mutation begins must finish verification or enter `ATTENTION_REQUIRED`, never report a false cancellation. One request emits one terminal result, including parser errors or disconnects. Fixture repeatability applies to host decisions and state, not LLM words/timing.

Conversation history lives only in process memory; on restart the app starts a new session. This avoids a chat database for the first MVP. Any future stored history requires a new storage ADR, retention policy and migration/recovery tests. A recovery journal for authorized file changes is separate security-critical persistence addressed by ADR-0003.

## Alternatives and rationale

- WebView-driven key entry, filesystem access and simple `approved=true` IPC make the renderer a privileged component. They are not accepted.
- Global native commands without per-window restrictions create a forged-webview path to privileged host operations. Use explicit allowlists, typed DTOs and negative caller tests.
- Automatic model tools, generic OpenAI-compatible provider switching and arbitrary URLs are outside the closed v0.1.0 registry. Adding them requires new threat and acceptance coverage.

## Validation and consequences

Fake-host tests must exercise both approved and hostile typed IPC, wrong/forged window, duplicate and out-of-order events, cancellation, root expiry and off-by-one limits. Windows native integration tests must prove dialog selection and root/file identity behavior before any file operation becomes active. Without them, the honest UI indicates file access unavailable or proposal-only. Build success on Linux alone does not verify the Windows-specific controls.
