Date: 2026-10-03. Status: accepted implementation design; execution evidence pending. Scope: SPEC-0003 / SEC-023/024, TM-024/025, AC-059/060, T-069/070.

The flag must share the caption-controls row. Do not grant generic renderer window/process APIs or install a shell/clipboard plugin. Add one strict main-window action command with only `minimise`, `toggle_maximise`, `toggle_fullscreen`, `start_dragging`, `close`; no arbitrary label, filesystem path, shell string or process. The trusted Rust host revalidates caller and state. Review-only/native secret operations remain independently owned and cannot be displaced. Guard OS close requests and the menu/shortcut close flow; no `process.exit`, forced destruction, reservation release or credential/data reset. A later failed/unsupported window action shows a safe local error.

Frontend bridge contract: optional `windowAction(input: {action: WindowAction}): Promise<{maximised: boolean; fullscreen: boolean}>` and optional `subscribeClose(callback: () => void): Promise<() => void>`. Native bridge implements both; legacy fake bridges may omit them and the corresponding controls must be unavailable rather than fake success. The host emits `aster://close-request` only to the main window when the normal close needs frontend draft review. Window controls/header markup/CSS are owned by the frontend implementation; Rust command, event routing, permission and native decoration configuration by the host implementation.

Unsent drafts remain bounded renderer memory, never a new private-store record or native secret. Navigation preserves them; review quit/close with default Cancel if nonempty. Clear only the deliberately discarded in-memory drafts. Undo/Redo, selected-text cut/copy/paste/delete use deliberate local editing with caret/range preservation; no continuous clipboard inspection and no native credential dialogue handler. Local find/zoom/sidebar/help/status change presentation only and never invoke send. Do not equate the default-cancel draft dialogue with security authority for native provider/file/credential operations.

Primary documentation reviewed 3 October 2026: [Tauri window customisation](https://v2.tauri.app/learn/window-customization/), [Tauri window API](https://v2.tauri.app/reference/javascript/api/namespacewebviewwindow/), [MDN clipboard](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard), [MDN execCommand](https://developer.mozilla.org/en-US/docs/Web/API/Document/execCommand). Prefer supported explicit edit state; execCommand is deprecated and cannot be assumed to implement dependable menu undo/clipboard in every WebView. Verify the actual locked Tauri/Rust/WebView contract and denied clipboard behaviour; documentation alone is not runtime evidence.

Native/installed clipboard-caption integration, accessibility, performance and owner acceptance remain NOT RUN until separately observed. This design grants no model capability or future provider call.
