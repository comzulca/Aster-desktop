# ADR-0006 — Creation-time private journal descriptors and retained admission

Date: 2026-09-30 UTC. Status: accepted for a dormant implementation candidate; execution NOT RUN. Trace: FR-014 / SEC-006, SEC-011 -> TM-014 -> AC-027 -> T-035 (privacy subsection only of T-031).

## Scope and authority

The current journal encrypts bounded metadata with current-user DPAPI and uses immutable CREATE_NEW records, but its path-only constructor does not establish directory/record ACL privacy. Strengthen only this internal seam. Do not add shipping IPC, a native approval, live request, project upload, process-kill driver, existing replacement or capability activation. Preserve schemas, bounds, no-clobber semantics and conservative recovery.

The existing owner account runs normally/non-elevated. New-object ACLs on exact app-created journal/fixture objects are storage implementation, not global Windows/security configuration. Never change an existing unrelated directory/file, selected project root, parent ACL, repository permission, real credential, security product, registry policy or account. Do not enable/adjust token privileges, take ownership, repair/relax an existing ACL, delete/recreate an existing object or silently migrate a weak journal.

## Closed descriptor policy

Obtain the current process user SID through bounded TOKEN_QUERY/TokenUser processing; validate and own only the bounded SID bytes. No renderer, model, argv, environment or caller-selected account may supply that SID. Directory creation uses a protected descriptor equivalent to `O:<SID>D:P(A;OICI;FA;;;<SID>)`; immutable record creation uses `O:<SID>D:P(A;;FA;;;<SID>)`. Exactly one full-control AccessAllowed ACE for the actual user, with the exact object-kind inheritance flags, is allowed. No Administrators, Users, Everyone, SYSTEM, inherited, callback/object/deny or extra ACE is admitted by this closed policy. SYSTEM/elevated administrators remain a residual regardless of listed ACEs; do not claim protection from privileged inspection.

Apply SECURITY_ATTRIBUTES at CreateDirectoryW and CreateFileW(CREATE_NEW), not in a post-creation chmod/repair window. Existing-object or creation collision is failure. Preserve no-delete ancestor/parent pins, OPEN_REPARSE_POINT, exclusive record-write sharing and same-handle identity/flush/hash checks. A creation failure leaves any ambiguous newly created state untouched for review; no production cleanup is introduced.

## Handle-bound admission and revalidation

Replace the path-only journal constructor with a fallible lifetime-bound borrow of the exact directory path, directory anchor, ancestor pins and expected identity. Validate NTFS eligibility, non-reparse directory identity, actual user owner and non-NULL/nonempty protected closed DACL through the retained handle. Security descriptor/ACL/SID/ACE reads must be bounded and validated before dereferencing fields; free OS allocations with matching APIs. Existing weak/foreign state is denied unchanged.

Revalidate directory/pins/identity/privacy before enumeration/read/persist and before success; validate each record's owner/protected DACL and file identity/link/reparse state by its retained handle before writing/decrypting and again before success. Recovery cannot return Verified if any privacy/identity check fails. Privacy drift after durable intent preserves ambiguous records/target and denies subsequent work; never report rollback, successful recovery or cleanup.

## Residuals and evidence

ACL checks are not atomic CAS against a malicious same-user process that can alter its own security objects; same-user compromise, privileged administrators/SYSTEM and physical power-loss remain separate risks. Metadata DPAPI plus a private DACL is not project-content persistence or multiuser authorization. Only fresh source-bound native fixtures can credit T-035. A privacy PASS does not pass aggregate T-031, owner native review, external-process competition/termination/restart, disclosure dispatch, existing replacement or issue #12. All four workspace flags remain false.

## Primary API contracts checked

Microsoft references inspected on 2026-09-30 UTC: [CreateDirectoryW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createdirectoryw) applies the supplied descriptor only on a filesystem supporting persistent ACLs and creates only the exact leaf; [GetSecurityInfo](https://learn.microsoft.com/en-us/windows/win32/api/aclapi/nf-aclapi-getsecurityinfo) reads the object selected by its handle, requires READ_CONTROL for owner/DACL and returns an allocation released with LocalFree, but expressly provides no race guarantee; [GetTokenInformation](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-gettokeninformation) uses TOKEN_QUERY for TokenUser and reports the required bounded buffer size. These API contracts support the design, not execution evidence or permission to alter existing user objects.
