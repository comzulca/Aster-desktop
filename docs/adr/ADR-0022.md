# ADR-0022 — policy rollover without reset; transactional attachment addition

Accepted for scoped implementation, 5 November 2026, before behavioural code. [SPEC-0007](../specs/SPEC-0007.md) / [threats](../security/THREAT-MODEL-0007.md).

1. Keep terms record schema/domain/hash-chain identity. Recognise the original 2026-10-02 revision and the current 2026-10-09 revision, validating accepted records against their own review window. Legacy acceptance restores as unaccepted for the current policy. Fresh native review appends a new record. Unknown records fail closed.
2. Centralise current review metadata, legacy boundaries and current expiry. Preserve the original financial policy for historical replay; the unreviewed 2–5 November gap stays inadmissible. Pricing is unchanged, so no historical quote is repriced. Old configurations are not extended. A current native budget configuration remains mandatory and never resolves pending charges implicitly.
3. Attachment custody stays in one process-local host registry. Snapshot the selected conversation's current opaque IDs before opening the selector; atomically check that exact snapshot on return. Expiry may invalidate the batch during selection, in which case the addition fails instead of resurrecting old grants. The operation lease continues to cover the actual native worker lifetime.
4. Validate the whole existing-plus-new allocation before mutating the registry. Cancellation returns current host metadata. Known pre-commit capacity/format/read failures retain the original batch; unknown/malformed receipts cause renderer cleanup. Full aggregate limits and earliest five-minute deadline apply to the union. Neither adding nor removing extends lifetime. Originals are never written to disk by this feature.
5. Keep the native exact JSON reviewer and its approval binding, not a renderer approval checkbox. Add policy provenance fields and a specific expired-policy message. Preserve the current UI geometry and product British English.

Consequences: a renewed build needs fresh owner terms/budget review. Repeated additions preserve documents only within the current draft's existing temporary lifetime and aggregate limits. Current key authentication still does not establish billing, account/territory eligibility or modality entitlement. This change does not require new dependencies or privileged IPC routes.
