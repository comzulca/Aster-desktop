## Resolved native PDF custody and bounded processing (owner confirmation)

The owner explicitly chooses sending the native PDF from a temporary copy, retaining only all processed page-images and responses, and reattaching the PDF for another complete native reading. Aster never deletes/modifies the owner's source file. Host memory contains a bounded immutable copy only during import/review/one dispatch; it is neither saved to history nor uploaded to the Files API. The first request uses the verified inline native PDF part. All-page rasterisation is a preview/history representation, not substituted native PDF egress. Restored processed pages are local display content; they do not restore a native PDF, attachment grant or approval. Continuation discloses the exact available prior text/answers and clearly labels the missing original; complete native rereading requires explicit new adjunction. No claim is made that a visual page preview reveals every hidden PDF object or establishes Contributor eligibility; the native review requires owner confirmation of the complete source, including hidden content/metadata.

Product bounds are independent of ChatGPT and stricter than the provider: four current attachments; immutable sources at most 8 MiB each and 16 MiB per current batch; 20 PDF pages total in a batch, all rendered at 150 DPI for processed display; image dimensions at most 4,096 each and 4,194,304 decoded pixels; one frame for GIF; at most 4 MiB of normalised PNG output per file, 16 MiB of processed PNG per batch and 64 MiB decoded RGBA per batch. Refuse rather than omit, crop, resize silently, select only some pages or truncate. Text/data files are strict bounded UTF-8, inert (no XML/YAML/JSON/formula execution); the composed prompt including text attachment context must still meet the inherited 32-KiB user-message bound. The 128-KiB individual/256-KiB aggregate parser text ceilings are hard defensive bounds, not promises that every such file fits the smaller sending bound. A larger text document can be converted externally to PDF by the owner.

Complex parsing runs in a fixed byte-only child worker assigned to an active-process-one, kill-on-close Job before parser execution, with 256-MiB memory, 10-second CPU and 15-second wall limits. A low-integrity/restricted token and absent secret environment reduce authority but are not independently verified no-network/RCE confinement; no network/file-path/converter authority is exposed by the worker protocol. Qualification must cover actual termination, fail-closed launch errors and native PDF/image processing, not just a thread timeout.

After Job termination/closure, one non-blocking worker-admission guard and a separate 1,000-ms/200-round cleanup attempt repeatedly cancel live owned I/O and join only completed, signalled threads. Incomplete cleanup denies and poisons further admission until process restart; at most three unfinished I/O closures may retain handles/bounded buffers until actual completion/process exit. This does not guarantee completed cleanup, physical secure erasure or OS scheduling/response. [ADR-0019](../adr/ADR-0019.md) fixes these source controls; complete actual-executable worker/resource/teardown qualification remains pending, distinct from the controlled held-pipe fixture's scoped P3 coverage above.
