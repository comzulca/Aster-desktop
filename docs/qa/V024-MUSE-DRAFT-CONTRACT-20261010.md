# v0.2.4 Muse-assisted inert draft generation — 10 October 2026

Before-code refinement of FR-032 / SEC-031,035 / TM-034,038 / T-089,093. This contract permits implementation, not live execution, completion or package qualification.

## Closed flow

`generate_customization` accepts only `{requestId,kind,description,dataClass}`. Kind is `skill` or `plugin`; the description is nonempty, at most 4,000 Unicode scalar values / 16,000 UTF-8 bytes and excludes non-whitespace controls. Contributor classification/admission applies to the complete native-authored generation prompt, not just the description. No package, path, original attachment, current conversation, Personalization, account or repository content is fetched or added.

The host creates a fresh ordinary conversation only after current-key authentication admission. A private, host-only generation origin leaves the main conversation, unsubmitted draft and temporary attachment registry untouched: creation does not invalidate originals and generation send does not even acquire or consume that registry. Generation requires an empty attachment-ID list. Neither origin nor conversation selection is renderer-controlled. Ordinary chat creation/one-use attachment consumption is unchanged. The host constructs a fixed bounded request asking for one inert package object `{kind,slug,name,description,instructions}` with the existing catalogue bounds. It passes the resulting prompt through the shared `send_message` disclosure, terms, durable budget, model registry, request-ID, cancellation, native key and transport pipeline, without changing those gates. This is ordinary Meta Chat Completions inference, not an OpenAI endpoint, privilege grant or structured-output guarantee. Each dispatch still requires the exact native human disclosure review; no configuration/personalisation consent replaces it. Failed preparation retains a truthful empty or failed generation conversation, never silently retries or discards history.

The receipt returns only the generated conversation ID and ordinary accepted request receipt. The renderer observes only matching conversation/request stream events; it caps received draft text, treats it as inert and makes a generated draft editable **only after completed** terminal status and strict package-shape/bounds checks matching the selected kind. Refused, stopped, malformed, oversized, failed or truncated responses cannot become saved packages automatically. A separate explicit Save invokes the revision-bound closed catalogue route. Generation never enables a package, connects an account, installs a dependency, runs a script, interprets a hook or changes a repository. Existing built-in IDs cannot be replaced. Ordinary local generation history records description/prompt and response; the UI discloses this. No clipboard, export, shell or filesystem authority is added.

The UI has its own request epoch, cleanup and cancellation. Native stream admission remains globally single-owner. A competing state change may deny preparation; it cannot grant authority. All actual network/native/cost behaviour remains NOT RUN during implementation. Headless fixtures verify explicit click, classification, isolation from local profile/repository/history, cancellation, request binding, unsafe draft rejection and explicit save; native/live acceptance remains separate.
