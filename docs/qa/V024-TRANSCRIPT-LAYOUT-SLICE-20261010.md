| Name | Exact role and bound |

| `HistoryId(String)` | Constructor/decoder permits 1–80 ASCII alphanumeric, `-` or `_`, matching current history IDs. No filename interpretation. Every retained string is independently bounded. |

| `ObjectRef`, `ChildRef`, `IndexNodeV1` | Fixed object ID/kind/digest/revision plus checked ordinal ranges. One index node has at most 128 children, 64 KiB encoded and depth 0–8. Purpose enforces allowed child kinds; no arbitrary external root. |
| `RootBinding`, `LayoutBase`, `RevisionChange`, `TranscriptCommitV1` | `RootBinding` adds fixed index depth/ordinal-range metadata to an exact `ObjectRef`; it is part of expected/observed base equality, not proof of an old object. The commit records structural roots/revisions, not legacy state, consent or summary content. |
| `ObservedLength`, `QuotaAccumulator`, `SuppliedInventorySnapshot` | Streaming supplied fixed-kind/ID/file-length inventory, current byte/count totals, ordered inventory digest and health category. Valid retained orphans consume the same quota as referenced objects. |
| `PreparedObject`, `PreparedBatch`, `PlanAdmission` | Bounded payload metadata only; no ciphertext or complete entry body retained in a batch. Exact supplied ciphertext lengths, expected/observed base and inventory binding, and one final commit determine structural plan fit. |
| `LayoutError` | Closed fixed categories: `Invalid`, `Limit`, `Overflow`, `Conflict`, `Integrity`, `Uncertain`. No raw content/path/native/provider errors in output. |

`BoundedList<T, N>` is a private helper with no unchecked public constructor: at most N elements, bounded capacity and checked push/custom deserialisation that rejects the next element before retaining it. No collection grows with lifetime history. No unrestricted `Vec` constructor, `serde_json::Value` tree or recursive general-purpose object parser is exposed. Parse input length first; retain typed fields only. Separate fragment/index/commit decode functions avoid a large inline enum carrying every payload type.

## Proposed local wire schemas and byte binding

These **candidate schema names/versions are internal test data**, not registered store protocols: `DisplayFragmentV1`, `IndexNodeV1`, `TranscriptCommitV1`, all `schemaVersion: 1`. Struct fields use `#[serde(rename_all = "camelCase", deny_unknown_fields)]`; closed enums use snake-case values as in existing history events. Typed parsing rejects duplicates, unknown/missing fields, malformed UTF-8/JSON, unknown variants, bad IDs/hashes, trailing material and wrong schema/tag. Do not reuse legacy record/conversation versions 1/2 or change their accepted fields.

Fragment fields are exactly: `schemaVersion`, `kind` (`display_fragment`), `conversationId`, `entryId`, `requestId`, `role`, `entrySha256`, `entryBytes`, `partOrdinal`, `partCount`, `byteOffset`, `text`. Index fields are exactly: `schemaVersion`, `kind` (`display_index` or `context_index`), `conversationId`, `revision`, `depth`, `children`; each child has `object`, `firstOrdinal`, `ordinalCount`. Object references have exactly `id`, `kind`, `sha256`, `revision`. Commit fields are exactly: `schemaVersion`, `kind` (`commit`), `conversationId`, `sequence`, `previousCommitSha256`, `change`, `baseDisplayRevision`, `displayRevision`, `displayRoot`, `baseContextRevision`, `contextRevision`, `contextRoot`.

Genesis is sequence 0, absent previous commit and roots, both revisions 0; its first plan is `Both` with sequence/revisions 1 and explicit bounded empty roots if no content exists. Non-genesis bases have positive sequence/revisions and both typed index roots. An empty index is permitted only as a depth-0 root with no range; non-empty children have positive ranges and strict contiguous increasing order. Display indexes accept only display-fragment/display-index children; context indexes accept only display-fragment/context-index children. New index descendants decrease in depth; new objects carry their respective planned revision. Exact old base-root cut points may retain their earlier revision/depth/range binding. The supplied fixed metadata for such old cut points is not verified old graph content; native checked replay remains a dependency. Context ranges describe selected-context order, not proof of display membership or eligible pairing. This validates a supplied bounded new graph only.

Use compact `serde_json::to_vec` over typed fields for each canonical payload. Hash exact encoded bytes with `sha2::Sha256`, rendered as lowercase hex, as existing history/media records do; raw-entry hash is over exact UTF-8 bytes. Prepared-object binding decodes under the kind-specific bound, verifies the scope/revision and requires exact equality to its canonical re-encoding before accepting the payload digest. A semantically equal differently escaped/spaced payload cannot silently substitute for bound canonical bytes. Do not hash unframed string concatenations or include an object's own digest inside its payload.

Proposed private operations are `split_entry(binding_ids, role, text)`, `encode_fragment` / `decode_fragment`, `FragmentAssembler::push` / `finish(expected_binding)`, `encode_index` / `decode_index`, `encode_commit` / `decode_commit`, `QuotaAccumulator::observe` / `finish`, `bind_prepared_object(kind, id, canonical_payload, supplied_ciphertext_length)` and `admit_plan(expected_base, observed_base, expected_inventory, observed_inventory, prepared_batch)`. Exact Rust signatures remain reviewable before code; none takes paths, a store, callbacks, credentials, approval booleans or network objects.

## Scalar-safe splitting and reconstruction

Input is one valid Rust UTF-8 string within the inherited role-specific ceiling. Reject NUL as current history does; preserve every otherwise admitted byte without trim, newline conversion, Unicode normalisation or text extraction. An empty assistant text produces exactly one empty fragment; an empty/whitespace-only user prompt remains denied. This is not full terminal-state or eligibility validation.

For each non-empty part, choose the largest `str` character boundary no more than 32,768 bytes from the current offset. Check additions/conversions; never slice through a multibyte scalar. Precompute canonical part count in a bounded scan, then stream fragments borrowing their exact slices. At most 32 parts are admitted per entry; this is sufficient for the unchanged 512-KiB bound under greedy scalar-safe splitting and is not a larger answer limit. Encode and size-check one fragment at a time, including JSON escaping/header overhead.

Assembly compares complete conversation/entry/request/role/hash/total/count bindings, expects each ordinal and exact byte offset, and checks each append against the per-entry byte cap. Reject missing, duplicate, reordered, overlapping, cross-entry and over-limit parts; retain failure as a terminal assembler error. At finish, check full byte count/hash and independently recompute greedy boundaries/count from the reconstructed bounded text, comparing the at-most-32 stored offsets/lengths. This rejects a noncanonical tiny-part partition without keeping every fragment body. Empty and CR/LF/tab/bidirectional/non-ASCII content distinctions are preserved where admitted.

## Fixed memory, object and index ceilings

All numbers below are **proposed slice-local test limits**, not activated storage capacity, renderer/native budgets or a guarantee that every workload can use 4 GiB:

| Quantity | Ceiling |
| --- | --- |
| Source/reassembled entry | 32 KiB user; 512 KiB assistant; one entry only |
| Raw fragment / parts per entry | 32 KiB / 32 |
| Encoded fragment / index or commit payload | 256 KiB / 64 KiB |
| Prepared object's supplied ciphertext length | Positive, at most 2 MiB; a provisional adapter ceiling, not measured DPAPI overhead |
| Children per index / depth | 128 / 8 |
| Objects per prepared transaction | 128 total, exactly one commit; no full payload/ciphertext batch |
| New index nodes / total new child references | 8 / 512 per transaction |
| Encoded plan metadata | 256 KiB; separately validate IDs/list limits before encoding |
| Existing inventory object count | 65,536 in the pure accumulator; no global ID list retained |
| Aggregate supplied ciphertext lengths | 4,294,967,296 bytes across data and commit objects, including retained orphans |

The object-count ceiling is an independent exhaustion denial and must later be reconciled with native enumeration/handle tests; it is not an early compaction trigger or a promise of usable capacity for all tiny-file patterns. Inventory scanning is incremental. Entry assembly bounds its retained text; one canonical encode/decode buffer is separately bounded. Do not claim exact total allocator/stack/DOM/process memory merely by summing logical payload ceilings. No full-history vector, all-payload cache or recursive unbounded graph is permitted.

## Checked quota and commit-last structural admission

`QuotaAccumulator` observes supplied objects in strict `(fixed domain-kind, RecordId)` order, retaining only the previous key, checked totals/count, hash state and health. Duplicate/out-of-order keys deny without a global growing ID set. Domain kinds are only candidate transcript data/control; legacy, media, finances and profile are not included or copied. Every supplied referenced, retained-orphan or partial object's exact file length contributes. Zero-length partial objects still consume an object count and mark inventory uncertain. Malformed/partial/uncertain health blocks new plan admission; a caller cannot relabel them as ignored free bytes.

The accumulator's result does **not** prove that a genuine complete native inventory was supplied. The future native adapter must establish completeness, identities, lengths, corruption checks and exclusive ownership independently. There is no native read, encryption, free-space measurement or quota reservation in this slice. Counts/hashes/status from a renderer are never inputs to a production admission boundary.

Plan admission first compares the full independently expected and observed base/inventory tuples, including conversation, commit sequence/hash, both revision/root identities, inventory epoch/digest/bytes/count/health. Mismatch denies before arithmetic. Check sequence increment and precisely the declared revision changes: changed revisions increment once and require different exact root hashes; unchanged revisions/roots remain identical. `ContextOnly` leaves display bytes/root/revision untouched. `DisplayOnly` does not implicitly add context eligibility. Root kinds/scopes/revisions match their respective purposes.

Validate a bounded prepared graph: new object IDs are unique, no current head/root ID is replaced, object kinds/scopes/revisions/digests match their canonical payloads, range arithmetic/order is checked, and every new data/index object is reachable from the final roots. Reject cycles, duplicate child aliases/leaf repetition within one root projection, inconsistent bindings for one object ID, dangling new references, incompatible purposes and unreferenced batch objects. One exact immutable fragment may be shared between the separate display and context projections; that intended sharing is not a cycle or duplicate prepared object. Old external cut points are allowed only as the exact independently expected base roots; unknown existing objects are not accepted by identifier alone. This does not prove that an ID is unused elsewhere on disk or that a supplied old root is healthy; native no-overwrite and checked snapshot evidence remain required.

The batch contains all non-commit descriptors first and exactly one matching commit descriptor **last**. Check that commit bytes/digest bind the expected base and final roots/revisions. Compute checked `existing_ciphertext_bytes + sum(all_prepared_ciphertext_lengths) <= 4 GiB` and checked prospective object count under the fixed ceilings. Exactly at the ceiling may fit; one byte over denies. Never subtract orphan/control/index bytes, assume plaintext length equals ciphertext length, discount a replaced root or reclaim a tombstone. Result `PlanAdmission` returns the bounded exact order/binding and prospective totals only; it performs no append or activation and cannot reserve bytes, imply readback success or allow dispatch.
