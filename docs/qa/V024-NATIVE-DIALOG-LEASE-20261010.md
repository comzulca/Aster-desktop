## Inspected ownership mismatch

`Host::enter_native_dialog` currently returns a guard borrowing its atomic busy flag. The async command keeps that guard while awaiting `spawn_blocking`, but the blocking closure owns only the document/window or file-picker inputs. A dropped async waiter can therefore drop the guard without stopping an already-started worker. The worker's native window may still exist. The same lifetime pattern appears in native credential entry, customization import, attachment selection, processed-media viewing and the shared exact-review helper. No actual owner dialog is opened during this review.

## Approved minimal source scope

Use a private, owned shared operation lease. Acquisition still uses the existing atomic compare/exchange and both closing checks; it admits no second operation while the flag is held. The final shared lease owner alone releases the busy flag. The async caller retains its own owner through the original whole-command scope, and every blocking native worker captures another owner **before** spawning. A worker retains that owner through all native review/visual stages and until its closure returns or unwinds. Dropping the caller or its join handle cannot release the worker's ownership. If a queued closure never starts, dropping that closure releases its own owner; the caller's remaining owner still governs the command.

Change only the private gate/guard ownership, host initialisation and explicit lease plumbing into the five worker kinds and shared review callers. This includes the four mechanical guard-reference arguments in `github_host.rs` for begin-connection, account confirmation, disconnect and repository selection; their authentication, epoch, cancellation, scope and token-publication logic stays unchanged. Do not move a state lock across an await, capture the complete Host in a worker, expose a new command, supply a caller approval or modify native owner validation, exact document/hash binding, cancellation/deadline semantics, credentials, persistence, grants, budgets, provider/GitHub endpoints or response contracts. Native approval remains move-only and is unrelated to lease cloning. Retaining a lease is not consent or a new capability. An unresponsive worker intentionally keeps later operations unavailable; do not release early to recover apparent responsiveness.

Pure fixtures must demonstrate exclusive acquisition, denial while either caller or worker owner exists, caller-drop with a retained worker, worker-drop while caller remains, final-owner release, unwind release, and two-phase closing denial. Inspect every blocking call site and every shared-review caller for a retained owner. These fixtures test ownership only, not OS dialog scheduling, cancellation delivery, installation or native consent. They may execute only in the already authorised disposable GitHub checks; no local native harness, app, setup or credential operation is authorised.
