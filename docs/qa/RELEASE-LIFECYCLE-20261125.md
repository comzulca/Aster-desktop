# Windows stable release lifecycle (2026-11-25)

Scope: PR only; no merge, release, installer launch, live Meta request or credential use.

- LC-01: Remove the calendar cutoff from new Windows builds. Gate **new Contributor dispatch** at 14 × 24 hours after the first qualifying newer version becomes available. Keep local history, reconciliation and in-flight request settlement available. Old installed binaries cannot be changed retroactively.
- LC-02: Qualifying evidence is the public GitHub Releases API for `comzulca/Aster-desktop`: not a draft or prerelease, a strictly newer canonical stable numeric version, and an uploaded, nonempty, version-matched Windows x64 NSIS installer. Use the later of release publication and first matching installer creation; take the earliest qualifying newer release, not the newest release, and do not restart the deadline on subsequent publications.
- LC-03: Missing, malformed, future or unavailable evidence cannot start a deadline. Retain previously observed deadlines in a distinct owner-protected store; a fetch failure does not revoke them. Read-only discovery on Windows starts at setup and repeats every six hours. Disable it under the existing CI live-network opt-out. Fixed HTTPS URL, no redirects, bounded time/response/pagination, no key, installation ID, conversation, attachment or download; GitHub can observe ordinary network metadata.
- LC-04: Credential verification, owner consent, per-request native disclosure and monthly London budget remain independent. Keep existing financial dates, ledger/terms bytes and legacy replay windows; validate new records under a new record version. No spending-cap or rate change. Once a v2 terms or budget record has been written, old binaries cannot replay it; do not downgrade over those stores.
- Threats: untrusted release JSON cannot supply URLs, open installers, publish changes or authorize Meta access; only validated fields can start a deadline. Local cache is advisory if unavailable so outages do not stop otherwise eligible use. Existing private-store controls apply; same-user tampering/rollback and wall-clock manipulation are not prevented. A device that never sees qualifying evidence cannot enforce it offline. Release owners must publish the real installer with the intended stable tag; removing published evidence does not retract a cached deadline for that version.
- Primary review: [Terms](https://dev.meta.ai/legal/terms-of-service) still dated 9 October; [geography and designation](https://dev.meta.ai/legal/geographic-use-policy) dated 9 November continues to list Muse Spark 1.3 Contributor; [pricing](https://dev.meta.ai/docs/pricing-rate-limits) still lists $0.10 input, $0.20 output and $0.002 cached input per million tokens; [overview](https://dev.meta.ai/docs/overview) still lists the exact direct API model. This is not account entitlement or legal advice. [GitHub API contract](https://docs.github.com/en/rest/releases/releases) supplies public release and asset metadata.
