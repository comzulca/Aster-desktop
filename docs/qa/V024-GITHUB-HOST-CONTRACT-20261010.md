# v0.2.4 controlled GitHub host contract — 10 October 2026

Before-code amendment to SPEC-0006 / TM-035–038 / ADR-0021 and the controlled integration contract. This is implementation intent, not live or native qualification. No real OAuth, credentials, external writes, owner app or installer is executed during implementation.

## Closed host slice and DTOs

Commands authenticate the fixed main window and use the existing host idle/native-operation guard. The model has no route. `get_github_status` returns `enabled`, `state` (`disabled`, `disconnected`, `authorising`, `connected`, `reconnect_required`), optional authenticated `account` (`id`, `login`), optional `repository`, optional `userCode`, fixed `verificationUri`, and `nextPollSeconds`. No access/refresh/device-code secret, arbitrary URL, credential target, raw network error or imported package authority is exposed.

Status option fields are serialized as explicit `null`, not omitted. The implemented DTO additionally exposes `inFlight` and fixed `mutationsAvailable=false`; the latter is an honest inactive state, not writable capability. Repository identities serialize as `installation_id`, `repository_id`, `owner`, `name`; list results contain `identity`, `private`, `canRead`, `canWrite`. A permission display is not an executable write grant. File results contain `path`, `branch`, `blobSha`, `content` and stay lower-trust/private local display data.

Explicit commands: `set_github_enabled(input:{enabled:boolean})`, `begin_github_connection`, `poll_github_connection`, `cancel_github_connection`, `disconnect_github`, `list_github_repositories`, `select_github_repository(input:{installationId,repositoryId})`, and `read_github_file(input:{path,branch})`. Enabling is a persisted preference only, never restored approval. Start requires separate native review of the dedicated App/fixed destinations; no secret/prompt is sent to Meta. Polling runs only after explicit UI intent and the host-owned monotonic minimum interval, with one in-flight operation, fixed expiry and no uncertain automatic retry. After every await, compare captured epoch before recording data or custody. Cancellation, disabling, disconnect and account switch invalidate pending epochs before further work. Late responses are discarded.

Integration refinement before host code: omit the duplicate `set_github_enabled` route and use the catalogue's existing revision-bound `set_customization_enabled` with fixed ID `builtin:github` as the sole persisted enabled preference. Disable invalidates runtime first; enable persists before updating runtime. The GitHub host exposes only a native-internal `set_enabled` transition. Runtime startup may restore the enabled preference, never account/session/repository/approvals or automatic network work.

The generated token pair is held only in zeroising native buffers. Fresh `/user` identity requires exact native account confirmation before fixed-target Credential Manager publication. Enumeration uses only installations for App 5256613, verified account identities and bounded native-selected repository IDs. Repository selection is separately reviewed and invalidates old proposals. Restored tokens alone never restore active account/repository/runtime rights; reconnect/revalidation remains required. Local forgetting is not remote GitHub revocation.

The fixed transport uses GitHub API version 2026-03-10, HTTPS-only github.com device/token endpoints and api.github.com named resource endpoints, no redirects/proxy override supplied by content, 10-second connect and 20-second request bounds, 4096-byte auth and 1MiB resource responses, at most ten pages of 100 entries. `scope=offline_access` is explicitly documented for GitHub App device requests (fresh primary documentation), not an OAuth-App-only assumption. Device-generated expiring tokens can refresh without Client Secret. A move-only permit requires verified durable `rotation_pending` before refresh; uncertain rotation or a restored pending marker requires reconnect, not replay. Application secret buffers are protected; the third-party HTTP/TLS/OS stack cannot be claimed to provide forensic zeroisation.

The controlled host further caps installed-scope enumeration at twenty requests and one thousand repositories within a 120-second operation deadline; each individual request and each next enumeration step is cancelled by the epoch watch. Cancelling an in-progress future does not undo a request already received by GitHub. Device expiry is conservatively bound to request start while the first poll waits at least the provider interval after receipt. Native account identity is re-read after confirmation and before custody publication. File reads freshly enumerate dedicated-App installed scope immediately before the bounded selected-file request; a generic public repository GET alone is not installed-scope proof.

Before-code inactive-adapter refinement: the current host deliberately requires explicit reconnection after token expiry/restart. Remove the unused refresh-network adapter instead of activating it to silence a compiler warning. Retain refresh-expiry validation only as an offline fixture and the reviewed custody/rotation scaffold as inactive source. The preceding protocol description is a deferred design, not an implemented refresh/rotation or automatic reconnect claim; no new endpoint is exposed or called.

File reads are one explicit bounded selected-repository intent, re-read stable repository identity, use fixed contents paths and encoded refs, reject traversal/ADS/sensitive names and non-text/NUL/oversized content, and return inert text/blob SHA. Private repository content is never automatically added to Meta, compaction, generation or Personalization.

### Before-code transient status consistency refinement

A native read operation temporarily moves the stored token out of `GithubHost` while retaining its authenticated account/selected repository and exclusive `inFlight` lease. That move must not emit `disconnected` with a selected repository: the existing renderer deliberately rejects that contradictory receipt. A current native in-flight operation with a retained authenticated account reports `connected` metadata while custody is temporarily owned by that operation. This is display consistency only, never a new dispatch grant; all command guards, epoch/cancellation checks, fresh installed scope and native confirmations remain unchanged. Authorisation without an authenticated account cannot manufacture connected status. Failure/disable/disconnect invalidates account, selection and the in-flight lease; no stale metadata is exposed outside connected state. Add pure source fixtures for the taken-token state, account-less in-flight state and cancellation invalidation without real tokens or network.

## Deferred authority and negative acceptance

All mutation, PR creation/integration and generic REST routes remain unavailable until separately implemented exact native proposals, immutable account/resource/revision/content binding and fresh rules/check/review revalidation are reviewed and tested. No renderer `confirmed` flag is admitted. Repository creation/deletion/admin/secret/workflow tools and arbitrary scripts/MCP remain absent.

T-090/091/092/096 fixtures cover fixed App/token shape, expiry/clock rollback, malformed/oversized responses, wrong account/installation/repository, disabled/stale callback and poll replay, exact native account denial/cancellation, restored pending rotation, unsafe file path/ref, and no private/profile egress. New fixtures and compiled checks do not prove live connection, native consent or actual account operations. Five source jobs, fifteen codecs/six resources, all 42 compound obligations, GLib and installed/live/production boundaries remain unchanged.
