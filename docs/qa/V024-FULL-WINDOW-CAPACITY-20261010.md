## Checked arithmetic, not implemented autocompaction

Let `W = 1,048,576`. Each output reserve is positive and no larger than the inherited 8,192-token ceiling; this does not introduce a new active output setting. For independently bound counts `Io` and `Is`, ordinary fit means checked `Io + Ro <= W`, and a required summary fit means checked `Is + Rs <= W`. Arithmetic overflow in the request being evaluated denies; it is not ordinary window exceedance and cannot trigger a summary fallback. These are **sequential distinct requests**: do not add both output reserves together or double-count reasoning. A 4,096-token summary reserve is a fixture value, not an approved active default.

Planning first validates the unchanged current context and candidate-before-append. It returns only ordinary-fits, summary-required-and-fits, or a denial/block. Ordinary window exceedance can propose summarising the older pre-append base only if that separately bound summary count fits; absent, wrong-prefix, stale or oversized **required** summary evidence blocks. An optional supplied summary's binding is checked even when ordinary fits, but its unused token arithmetic is not evaluated in that branch. A well-bound unused over-window or `u64::MAX` summary count therefore does not invalidate ordinary capacity; it never qualifies that summary or proves future headroom. Pin this distinction in a synthetic fixture. Do not append the new turn, lose its prompt, replace display history, truncate media or make any network/storage transition. Equal supplied counts on either side of the old 512-KiB text boundary receive the same capacity decision; no turn-count input or early 20-turn trigger is present.

**Important limitation:** this core alone cannot guarantee that a summary will remain possible after a later answer. Count/template tokenisation is not generally additive after append/re-encoding. A preventive watermark must independently qualify the real summary representation and conservative carry-forward/template bounds, or separately count a complete proposed summary representation. Do not manufacture that proof from ordinary output tokens, label this core active automatic compaction or claim full-window delivery. The actual count route may also reject an over-limit candidate; future orchestration must handle that without losing the admitted prefix or silently substituting a partial count.
