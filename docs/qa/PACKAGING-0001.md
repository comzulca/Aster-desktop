# PACKAGING-0001 — unsigned engineering installer gate

Status: **NOT RUN** at design time. This is a procedure for producing a private evaluation artifact, not evidence that the app is installed on Windows 11 or eligible for production.

After the `source-policy`, `frontend`, and `windows-host` jobs all pass on the same `main` commit, the `engineering-installer` job on hosted Windows Server 2025 may build one NSIS setup executable using the pinned Node 22 and Rust 1.97.0 inputs. It runs the Tauri CLI with `--ci --no-sign`, rejects changed lockfiles and an unexpected executable count, verifies that Authenticode reports `NotSigned`, then uploads the executable and a JSON manifest with exact source commit, workflow run/attempt, filename, byte count and SHA-256. Its private GitHub Actions artifact expires after 14 days. The ZIP-level artifact digest and executable SHA-256 refer to different bytes and must never be interchanged.

Before using an artifact on a Windows 11 laptop, verify the GitHub workflow and manifest refer to the desired source revision; hash the downloaded executable locally with `Get-FileHash -Algorithm SHA256` and compare it with `sha256` in the manifest. Check the original JPG hash from `README.md` in source. This installer is explicitly unsigned; no claim is made about SmartScreen/ESET acceptance, installed behavior, Windows Credential Manager on the user's account, native file mutation, either NVIDIA live model or bit-for-bit reproducible bundling. Keep Windows and security software protections active. A signed production installer needs separate signing custody, final binary identity, Windows 11 install/uninstall and accessibility tests, and a promotion decision recorded against that exact binary.
