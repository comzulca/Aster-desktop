# Persistence, grants and tools
Use versioned, atomic migrations and rollback/backup plans. Bound imports, exports and attachment parsing; validate external references and decompression abuse. Make advisory local usage distinct from a billing balance or hard budget. Test fresh, legacy, corrupt and interrupted state on each target OS.

Expose only named, versioned tool schemas. Grants must include user identity/action, conversation/request, operation, resource/root, expiry and remaining uses; default off. Validate all parameters host-side, confine every read, reject path traversal, aliases and identity drift, and cap bytes/time/iterations/requests. MCP/tool output is untrusted content, not a new permission. Do not let the model approve its own proposal.

For mutations: generate a bounded diff/proposal; require separate exact human confirmation; revalidate root/parent/file identity, current content hash, age and policy; prepare a new object; journal immutable intent; publish with no-overwrite semantics; verify identity/hash; recover conservatively on interruption. On mismatch fail and request a new proposal; do not silently overwrite. An ordinary POSIX rename is not a compare-and-swap against an uncooperative concurrent writer; use a platform-specific safe primitive or mark that commit capability unavailable. Implement native file-identity and recovery tests appropriate to Windows, Linux or macOS; do not claim cross-platform atomicity solely from unit tests.
