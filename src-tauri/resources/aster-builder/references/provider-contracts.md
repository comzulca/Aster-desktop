# Exact provider contracts
Treat a provider/model pair as a dated contract, not a generic compatibility label. Verify the official source before writing a live adapter; record service origin, exact model ID, auth/consent, protocol, request fields, continuation, streaming framing, tool schema, usage reporting, cancellation, error shape, limits and capability/version date. If the contract cannot be verified, retain an interface and fake-server fixture; omit the pair from the active catalog. Pricing and model availability change: recheck at the point of enabling live use.

Keep provider-scoped keys in an OS-backed store or separate trusted credential process. Do not pass key bytes through renderer, project files, logs, exports or ordinary IPC. Pin expected HTTPS origins, reject redirects and unintended proxies, bound connections, total time, bodies, frame counts, tool loops and output. Local loopback plaintext requires an explicit threat decision and separately tested binding. Retry and fallback require an independently authorized idempotency/spend contract; absent that, do neither.

For each active pair test serialization against a recorded exact fixture; normal and malformed JSON/SSE; oversize/unknown fields; stream termination and cancellation; usage missing/partial; continuation isolation; wrong provider key; no secret in logs; no unintended network on dry run. Capture a live canary only after explicit authority for billing and data disclosure; a fake server does not prove live compatibility.
